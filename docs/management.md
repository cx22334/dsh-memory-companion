# 记忆管理界面

管理页面与 DSH 聊天界面分开运行，只监听本机回环地址。`startManagement(service)` 返回 `{url, baseUrl, token, close}`；停用时返回 null。`url` 中的访问令牌在首次打开后从地址栏移除，仅留在页面内存，不写 localStorage。关闭服务会失效本次令牌。

提供日记与原文对照、手写与编辑、完整/部分撤回、排除来源、恢复、锁定、使用策略、整理提议、实际注入快照、候选预览、隔离回放、补记、时间线、索引维护和完整导出。角色读取声明以原生占位符生成，供使用者放入人设 prefix；页面不会偷偷更改人设或替角色授权。

候选预览只调用检索，回合编号以 `management-preview:` 开头，界面明确标为未发送给聊天模型；它保留审计快照，但不会产生真实对话事件或日记。需要比较完整回答时再由用户触发隔离回放。

用户不指定 DSH 会话时，管理操作采用持久的 `management:<role>:<context>` 专用绑定，只读取该角色和公共范围，用于恢复后台管理任务。它不会伪造原始对话事件；指定实际 DSH 会话时则直接采用已登记的真实绑定。暂停任务的重试是明确用户操作，前次调用结果未知时需要另行勾选允许重新请求。

编辑请求携带 expected_revision；审批携带 proposal_hash。部分撤回的选区转为原正文 UTF-8 字节范围，只有使用者预览并提交的 approved_body 才能成为新的可用修订；没有安全完整正文时不自动拼接剩余内容。恢复原文来源需要明确操作 ID，普通恢复不会顺带放开来源限制。

访问控制包含随机 Bearer 凭据、独立 CSRF 凭据、Host/Origin 检查、CSP、禁止嵌入、请求体上限及固定静态文件映射。页面不渲染记忆中的 HTML，不执行 Markdown 中的脚本。`management.exportRoot` 是操作人员配置，默认在记忆库旁的 `memory-exports`；页面只能提供导出名称，不能提供任意目的路径。

这些措施不能代替模型工具的 OS 隔离。管理 URL 不应进入模型上下文或模型可读会话日志；由独立本地 CLI 向使用者显示。模型可控浏览器同样不应继承管理会话。当前宿主适配无法安全清理已发送历史时，使用者应新建不继承旧历史/摘要的会话；页面没有伪造一个“已经清理”的按钮。

UI 使用已定的日记管理工作流，参考了 dsh-vcprag 的分页管理思路，但未整体复制其宿主 React/remote 接口代码；本地服务没有新增第三方运行时依赖。依据用户要求，本次只写代码，未运行测试、lint、类型检查、试启动或浏览器检查。
